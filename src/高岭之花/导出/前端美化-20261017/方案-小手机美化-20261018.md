# 高岭之花 · 小手机美化 · 方案（手机 + APP 形态）

> 日期：2026-10-18
> 基线：`导出/前端美化-20261017/前端美化.html + .vue`（设置整合版，含人体图融合实装）
> 状态：方案待用户确认 → 先做示例审核 → 再实装
> 定位：独立新系统；失败可整体回退，不影响现有终端形态

---

## 〇、设计目标：让终端"像手机"，而不是"是手机"

不做手机外壳、刘海、实体按键——**保留现有面板的方角与配色体系**，只通过布局与交互让人一眼觉得"这是一台手机界面"：

1. **布局像手机**：顶部状态栏 + 主屏桌面 + 底部 dock，三层结构。
2. **应用像 APP**：现有六大面板 + 设置，变成主屏上的应用图标；点开是全屏内容页，可返回主屏。
3. **氛围像手机**：主屏有壁纸感（主题色渐变 + 装饰），角色信息做成"小组件卡"，图标有圆角方块质感。

风格硬约束：所有颜色/圆角/间距/字体沿用现有 CSS 变量（`--bg / --panel-2 / --accent / --line / --font-mono`），不引入新色系。

## 一、界面结构（自顶向下）

### 1.1 状态栏（新增，模拟手机顶栏）

一行三区，沿用现有信息面板顶部的数据：

| 区 | 内容 | 来源 |
|---|---|---|
| 左 | 时间 + 日期 | `timeText`（如 08:40 · 4月7日） |
| 中 | 角色名 + 运行状态点 | 白峰千鹤 · 运行中（`statusText`） |
| 右 | 电量图标 + 信号图标 | `hbBattery` / 装饰图标 |

样式：半透明底 + 细线分隔，mono 字体小号字，与现有 `chat-head` 一致。

### 1.2 主屏（新增 home-view）

从上到下：

1. **壁纸区**：主题色对角渐变 + 微弱网格/光斑装饰（`background: radial-gradient` + `var(--accent-dim)`，纯 CSS，不引图）。
2. **角色小组件卡**（像手机锁屏信息 / widget）：
   - 头像（现有 `avatar` 组件）+ 白峰千鹤 · AN-0170A + 运行状态
   - 一行摘要数据：电量 / 好感度 / 敏感度（复用现有核心数据）
   - 点击 → 进入「状态」APP（可选交互，见待确认 Q3）
3. **APP 网格**：4 列 × 2 行，共 8 个应用图标（见 §2）。
4. **Dock（底部）**：2 个常驻 + Home 指示点：
   - 「对话」→ 返回聊天视图
   - 「设置」→ 打开设置 APP
   - 中间 Home 指示条（装饰，点击回到主屏顶部）

### 1.3 APP 页（复用现有面板内容）

- 顶部 **APP 头**：左「‹ 返回」（回主屏）+ APP 名 + 右侧小 tag（沿用 `panel-tag` 风格）。
- 内容：对应面板现有全部内容直接迁入（不重写逻辑）。
- 底部：Home 指示条（点回主屏）。

### 1.4 返回与状态机

```
view: 'chat' ⇄ 'home' ⇄ 'app'
app: '状态' | '躯体' | '认知' | '记忆' | '指令' | '系统' | '设置'
```

- `view='chat'`：现有对话视图（不动）。
- `view='home'`：小手机主屏（新增分支）。
- `view='app'` + `app='状态'`：打开对应 APP 页。
- 返回路径：APP → 主屏 → 对话；主屏 dock「对话」直达聊天。
- 实现：沿用现有 `view` 变量扩展 + 新增 `homeMode` 开关，不引入路由库。

## 二、APP 清单（主屏 8 图标）

| 图标 | APP 名 | 内容 | 数据/复用 |
|---|---|---|---|
| 脉冲波形 | 状态 | 状态总览 / 机体总览 + 液体储备 / 运行参数 / 时间地点 / 认知简述 | 现有状态页整体迁入（含已实装人体图缩略图+液位计） |
| 人体剪影 | 躯体 | 完整机体结构图（L1/L2/L3、缩放、详情、舱门/锁定联动）+ 维护舱门按钮 + 身体锁定 + 实际着装 | 现有躯体页整体迁入（已实装） |
| 芯片 | 认知 | 身份认知 / 自我认同 / 人格摘要 | 现有认知页迁入 |
| 记忆 | 记忆 | 记忆日志 / 标签编辑 / 新增记忆 | 现有记忆页迁入 |
| 终端符号 | 指令 | 指令覆盖列表 / 添加删除指令 | 现有指令页迁入 |
| 系统齿轮 | 系统 | 系统日志 / 异常上报 / 终端命令 | 现有系统页迁入 |
| 调色板 | 设置 | 现有设置面板（含「小手机模式」开关） | 设置视图迁入 |
| 对话气泡 | 对话 | 返回聊天视图 | 直达 `view='chat'` |

> 图标全部内联 SVG，沿用线性圆角风格（与已重绘的 panel-icon 一致），底为圆角方块 + `var(--accent-dim)`，选中按压态用 `--accent`。

## 三、形态适配

| 形态 | 呈现 |
|---|---|
| 手机形态 | 「终端」底部按钮改为进入主屏；主屏/APP 全屏于面板区域（保留现有 phone 布局与底部导航） |
| PC 形态 | 右栏整体变为主屏/APP 界面（不改变双栏骨架，左聊天右小手机） |
| 自适应 | 随现有 `effectiveMode` 自动切换，样式共用一套主屏组件 |

两个形态共用同一套 home/APP 模板与逻辑，仅容器宽度不同（沿用现有 phoneVars / pc 布局）。

## 四、与人体图融合的关系

- 躯体 APP = 现有躯体页完整人体图（不做任何改动，直接迁入）。
- 状态 APP = 现有状态页（含机体总览 + 液体储备左右并排）。
- 即：**本次已实装的人体图功能原样保留**，只是入口从底部标签变成主屏图标；经典模式（开关关）下六标签形态不变。

---

## 五、独立开关与兼容

- 设置页「形态」分区新增开关 **「小手机模式」**（`homeMode`）：
  - 开（默认）= 主屏 + APP 形态（本次改动生效）。
  - 关 = 现有六标签 app-view 形态（原样保留）。
- 两形态可随时切换对比；若最终不采用小手机，关闭开关即完全回退，无残留。

## 七、待确认项（Q）

- **Q1**：APP 拆法——「八个独立 APP（如上）」还是「控制终端一个 APP 内含六面板」？（本方案按前者设计，更接近真手机；若选后者改动更小）
- **Q2**：主屏网格列数——手机形态 4 列 / PC 形态 6 列，还是两形态统一 4 列？（本方案建议统一 4 列，观感一致）
- **Q3**：角色小组件卡点击行为——点击进入「状态」APP，还是纯展示不可点？
- **Q4**：小手机模式默认开关——默认开（本方案）还是默认关先对比？
