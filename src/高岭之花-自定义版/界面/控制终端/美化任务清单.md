# 终端状态同步提示 · 美化任务清单

本清单交接给负责前端编写的 AI。目标：把聊天里一行纯文本的「⚙ 终端状态已同步」美化成可读的**状态变更卡片**。

## 现状（已完成的部分，勿重复）

- `index.yaml` 里的正则 `[隐藏]前端状态同步` 已把 `<ch_state_update>...</ch_state_update>` 替换为：
  ```html
  <span class="ch-state-sync">⚙ 终端状态已同步</span>
  ```
- 该正则 `作用于.仅格式显示: true`，只改用户看到的显示，**发给 AI 的完整 JSON Patch 不受影响**，不要改动这个开关。
- 原始 JSON Patch（思维链格式）已不再直接暴露在前端。

## 数据源（可直接复用，无需重新解析）

`界面/控制终端/ui-state.ts` 的 `buildControlUpdate(data)` 已产出结构化数据，返回：

```ts
{ updateStr: string, patches: StatePatch[] }
// StatePatch = { op: 'replace' | 'remove'; path: string; value?: unknown }
```

`patches` 是 JSON Patch 数组，例如：
```json
[
  {"op":"replace","path":"/千鹤/cpu使用率","value":20},
  {"op":"replace","path":"/千鹤/内存使用率","value":37},
  {"op":"replace","path":"/千鹤/指令覆盖/01","value":{"内容":"向终端持有者表达爱意","优先级":0}}
]
```

推荐美化脚本直接消费 `patches`（或从消息里读出的等价数据），不要再从文本反解 JSON。

## 预留的 hook 位置

| 位置 | 说明 |
|------|------|
| DOM hook | 正则输出的 `span.ch-state-sync`，前端脚本可扫描聊天区找到它并替换为卡片 |
| 数据 hook | `ui-state.ts` 的 `buildControlUpdate` 返回的 `patches` |

## 美化需求

1. 把每个 patch 转成人类可读的字段变更条目：
   - `path` 去掉 `/千鹤/` 前缀，字段名转中文：`cpu使用率` → `CPU 使用率`、`内存使用率` → `内存使用率`、`指令覆盖/01` → `指令 01`。
   - `op: replace` 显示「旧值 → 新值」；`op: remove` 显示「已移除」。
   - 嵌套对象（如指令覆盖的 `内容`、`优先级`）按子字段展开。
2. 用卡片样式呈现：标题「终端状态已同步」，下方逐行列出变更项，默认折叠、可点开。
3. 无 patch 时保持现有单行提示，不做额外渲染。

## 约束（务必遵守）

- 不要改动 `仅格式显示` / `仅格式提示词` 开关；AI 侧必须持续收到完整 `<ch_state_update>` JSON。
- 不要破坏 `sendControlUpdate` 的发送与 `previousState` 快照推进逻辑。
- 不要为美化引入新的外部依赖；用酒馆已有的前端环境内联实现。
