# 设计交接 · 高岭之花「开局与角色」系统重做

> 给接手的设计 AI。本文件只含**方向、素材与约束**，不含任何现成设计稿。
> 上一轮所有视觉方案已被整体否决，**不要打开 `设计交付-开局与角色/` 目录下的任何文件（`方向总览.html`、`设计说明-开局与角色.md`）作为视觉参考**——它们只记录被否掉的错误，读它们只会污染新设计。

## 1. 任务

为 SillyTavern 角色卡《高岭之花 · 白峰千鹤》（仿生机器人 + 控制终端 MVU 卡）重新设计「开局与角色」系统，覆盖五块：

1. 首次打开入口
2. 官方角色（千鹤）浏览与开场选择
3. 自定义角色创建 / 编辑
4. 角色库与导入导出
5. 游戏内入口

只改 `src/高岭之花-自定义版/`，**禁止改动稳定版 `src/高岭之花/`**。

## 2. 已确定的方向（用户拍板，不可改）

- **首页 = 翻页器，多页并列**。页 1 自定义，页 2 千鹤，……尾页管理。尾页恒为管理（导入导出 + 设置）。未来新增角色在中间插页，页签可扩展。
- **每页只放**：图 + 标题 + 一句话简介 + 一个开始按钮。点击进入对应子页（自定义流程 / 千鹤详细信息 / 管理）。
- **开场白不在首页选**。在千鹤子页内选择三条开场白。
- **三个预设 = 三个不同的故事**（初次连接 / 单独辅导 / 恋人关系），不是三个场景或世界。开场白 = 卡内原本的第一条信息（首楼），选中哪条，开局第一条就是它。
- **自定义 = 用户自己的角色，与千鹤无关**。立绘先用占位符，图片由用户后续自备。
- **官方与自定义在入口并列**（翻页式），无主次、无上下位。

## 3. 用户明确否过的（禁止重复）

- 老首页：等大入口卡片、浅色底、居中、每入口一个按钮、强制三步流程、无草稿。
- 用材质/道具区分官方与自定义（机器人→工房/人偶/零件；档案→印章/红绳/牛皮纸；终端→CRT/绿字；日式→竖排宋体+朱砂）。
- 只做入口页，不答编辑、存储、导入导出。
- 八股与过度描写、过度介绍解释（"赋能/旅程/命运"类措辞零容忍）。要求：**元素清晰、引导优秀**，每屏一眼看懂往哪走；文案克制、具体、可执行。

## 4. 每个方案必须回答的问题

1. 第一屏主体是什么？
2. 官方与自定义靠什么区分？（用结构区分，不是材质）
3. 自定义 / 官方谁优先？—— 必须并列。
4. 草稿是什么状态？（建议：草稿 = 从未「开始」的记录；自动保存；「开始」才写首楼）
5. 编辑如何自由跳转？（不做强制线性步骤）
6. 角色库 / 导入导出在哪个层级？（尾页管理 + 库入口）
7. 游戏内入口？（设置 hub / 当前角色展示）
8. 移动 / 桌面排法？—— 移动优先；桌面版此前被批「太烂」，必须认真做，不能是移动版的简单放大。

## 6. 技术约束

- Vue3 + scoped SCSS；SillyTavern / Tavern Helper；移动优先（375–430 宽），桌面双栏及以上。
- 根节点禁 `position:fixed`；覆盖层 `position:absolute; inset:0`，父级 `.phone` 为 relative。
- 沿用现有 CSS 变量，不新增配色；文案中文克制具体。
- 先以独立文件交付（HTML 总览 + MD 说明），用户审核后再落源文件；不要直接改源文件。

## 7. 交付物要求

每个方向 = 美术方向说明 + ≥5 屏高保真（首次打开 / 官方浏览 / 自定义编辑 / 角色库与导入导出 / 游戏内入口）+ 交互说明（状态流转 / 空态 / 错误 / 校验 / 自动保存 / 导入冲突 / 删除确认）+ 移动与桌面各一套排版 + 实现备注（组件拆分 / 复用文件 / 新增数据字段）。

交接书建议先每方向各出 1 张主入口高保真，供用户选方向后再展开。
