## 1. 任务

为一张 SillyTavern 角色卡《高岭之花 · 白峰千鹤》重新设计「开局与角色」系统，包括：

1. 玩家第一次打开卡时的入口；
2. 官方预设角色（白峰千鹤）的浏览与开场选择；
3. 自定义角色的创建、编辑、开场编写；
4. 角色/开场的本地存储、草稿、导入、导出；
5. 游戏进行中的入口（设置里的角色库）。

需要 2–3 个**完整的美术方向**，每个方向给出高保真界面与交互说明；不是三个布局变体。

## 2. 项目背景

- 这是一张以「仿生机器人 + 控制终端」为核心的 MVU 角色卡，主角是白峰千鹤（AN-0170A），玩家通过终端控制她。
- 卡内已有一个“控制终端”界面：状态、认知、记忆、躯体、指令、系统六个页签，移动端为主，PC 为双栏。
- 现在要做的是**终端之外**的开局与角色管理，不要把终端界面直接套过来。
- 用户重视：去八股、去机器人化、去绝望、禁止刻板印象；文案克制、具体、不堆形容词。

## 3. 当前实现（可复用，也可推翻）

### 流程

- 卡的首楼是一句占位消息：`<!-- ch-opening-pending --> 终端正在初始化……`
- 首楼界面检测到占位且聊天变量 `ch_opening_done` 未置位时，显示开场流程。
- 选完开场后：替换首楼文本 → 写入 `stat_data` → 置完成标记 → 重载。
- 开场只写一次；旧聊天没有占位标记就不会弹。

### 现有开场流程（已被否）

`src/高岭之花-自定义版/开场/OpeningFlow.vue`

- 首页：三块等大入口（官方/自定义/导入）；
- 官方：千鹤档案 + 3 条开场 + 预览；

## 4. 用户已明确的要求

1. **开局自定义不一定要长得像控制终端**。风格可以一致，但形态不必是终端/手机壳；要有“游戏入口”的感觉。这里说的是设计结构，不是美化。
2. **入口设计现在很怪**。虽然区分了官方与自定义，但区分方式不成立；可以**自定义优先**，或者用更强的方式把两者分开。
3. **预设存储/导入/导出太单一**：
   - 现在只有“保存到角色库”，没有**草稿**与**立即暂存**；
   - 没有自动保存、恢复草稿、批量导出；
   - 导入导出只有单角色 JSON。
4. **自定义不能强制“下一步”**。各板块要能自由跳转，随时改、随时存、随时开始。
5. 官方角色只读；可以「复制为自定义」再改（方向已定，未实现）。
6. 自定义默认建一个主角，也允许再建更多角色；角色管理器需要优化（样式与功能）。
7. 世界设定：既要**完整世界编辑**，也要有方便的轻量设置。
8. 存储：IndexedDB 角色库 + JSON 导入导出（已定）。
9. 入口：首次启动页 + 游戏内设置里的「角色与开场」hub（已定）。

## 5. 已否决的东西（不要重复）

- 等大卡片网格、浅色底、居中排、每个入口一个按钮；
- 三套“结构线框”当设计交付；
- 用现成符号替代设计：
  - 机器人 → 工房/人偶/零件；
  - 档案 → 印章/红绳/牛皮纸；
  - 终端 → 扫描线/CRT/绿色荧光字；
  - 日式 → 竖排宋体 + 朱砂。
- 用“材质/道具”来区分官方与自定义（书脊、封签、虚线草稿纸等）；
- 强制线性步骤；
- 只做入口页，不回答编辑、存储、导入导出。

用户原话：“这些方案都烂完了，太死板，太廉价，太垃圾”“刻板印象又犯病了是吧”。

## 6. 设计必须回答的问题

1. 第一屏的主体是什么？
   - 角色立绘 / 纯排版文字 / 空白创作画布 / 直接进终端 / 其他。
2. 官方与自定义靠什么区分？
   - 信息权限（只读 vs 可编辑）、内容来源、编辑状态、入口层级……不能靠道具和材质。
3. 自定义优先，还是官方优先？如果是自定义优先，官方入口怎么不显得像附属品？
4. 草稿是什么状态？
   - 自动保存的临时版本，还是显式“暂存”？
   - 草稿与正式保存怎么区分、怎么恢复、怎么丢弃？
5. 编辑时如何自由跳转？
   - 侧栏/顶栏/分段锚点/单页滚动；如何显示完成度与校验，但不强制顺序。
6. 角色库、开场库、导入导出在哪个层级？
   - 一级页面、抽屉、设置内；单角色导出 / 全部导出 / 只导开场。
7. 游戏进行中从哪里进？
   - 设置 hub、终端头部、独立按钮；入口图标/文字如何与终端视觉一致。
8. 移动端与桌面端分别怎么排？
   - 手机 375–430 宽；桌面双栏；同一套信息架构。

## 7. 约束

- 技术：Vue 3 + scoped SCSS；SillyTavern / Tavern Helper；移动端优先。
- 主题：沿用现有 CSS 变量（`--bg`、`--panel`、`--line`、`--accent`、`--text`、`--muted`、`--red`、`--font-mono` 等），不新增一套配色；如要调整，给出理由与映射。
- 根节点禁止 `position: fixed`；覆盖层用 `position: absolute; inset: 0`，父级 `.phone` 为 relative。
- 文案：中文、克制、具体；不要“赋能/旅程/命运”这类八股。
- 不修改稳定版 `src/高岭之花/`，只改 `src/高岭之花-自定义版/`。
- 输出要能落地：给出尺寸、间距、字号、状态、交互，不只给概念图。

## 8. 交付物

每个方向一套：

1. **美术方向说明**：一句话主张、字体、色彩、构图、动效、为什么适合这张卡；明确说明如何避免上述刻板印象。
2. **高保真界面**（至少 5 屏）：
   - 首次打开；
   - 官方角色浏览 / 开场选择；
   - 自定义编辑（自由跳转、草稿状态）；
   - 角色库 / 导入导出；
   - 游戏内入口。
3. **交互说明**：状态流转、空态、错误、校验、自动保存时机、导入冲突、删除确认。
4. **移动端与桌面端**各一套排版。
5. **实现备注**：组件拆分建议、可复用现有文件、需要新增的数据字段。

建议先给 2–3 个方向各 1 张主入口高保真，让用户选方向，再展开完整 5 屏。

## 10. 验收标准

- 第一眼不像“网页表单”或“后台管理”；
- 官方与自定义的区分来自结构与权限，不来自装饰道具；
- 自定义可以在任意板块之间跳转，随时暂存/离开/回来；
- 草稿、正式保存、导入导出三者的关系一眼能懂；
- 移动端单手可完成“新建角色 → 写开场 → 开始”；
- 不出现第 5 节列出的任何套路。
