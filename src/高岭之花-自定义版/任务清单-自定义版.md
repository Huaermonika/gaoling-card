# 高岭之花 · 自定义版 · 任务清单（初稿 v3）

> 状态：初稿 v3，已并入 2026-11-03 的全部拍板；剩余待定见第七节。
> 工作位置：`src/高岭之花-自定义版/`（稳定版 `src/高岭之花/` 只读）。
> 基线：V1.6.3 的完整复制；本版不兼容旧存档。

## 一、目标

把固定主角「白峰千鹤」替换为可被玩家补全的角色槽位；玩家以**控制终端持有者**的身份操作一个或多个仿生机器人。舞台不限定在学园，也不再有「投放测试」框架。终端上可切换当前显示与控制的角色，修改只作用于对应角色。千鹤保留为内置预设并作为默认角色。

## 二、已定口径

| 项 | 结论 |
| --- | --- |
| 可自定义字段 | 姓名（必填）、外观、性格、初始认知、背景、关系、型号、语言习惯、其他（均选填） |
| 角色本质 | 默认为机器人（控制终端只能控制机器人） |
| 受控角色 | 完整状态 + 完整记忆，可被终端切换与控制 |
| 背景角色 | 仅基础属性（姓名 / 外观 / 关系 / 备注），不记记忆、不记运行状态 |
| 角色优先级 | 仅受控角色有；默认第一个为最高；决定记忆配额与项目权重 |
| 记忆配额 | 三档：优先级 1 = 12 条 / 2000 字；2 = 8 条 / 1200 字；3 = 5 条 / 800 字（可调） |
| 千鹤 | 内置预设，默认角色（其学园背景属于她的个人档案，不上升为世界观） |
| 世界观 | 基本设定不变：现代日本、仿生机器人隐秘存在、控制终端；**舞台不限学园**；**取消投放测试**；玩家身份 = 终端持有者 |
| 档案注入 | 脚本每轮注入当前角色档案块（世界书只留规则） |
| 旧档兼容 | 不做兼容，只开新档 |
| 开局入口 | 卡内向导与外部预设工具并存，比例后续细化 |
| 次要分支 | 明日方舟拓展，排在本分支之后，暂不启动 |

## 三、架构草案

### 3.1 变量结构（v2）

```text
世界: { 当前时间, 当前地点, 近期事务 }
当前角色: string            # 角色 id，默认「千鹤」
角色: record<id, 角色>
主角: { 持有者: { 称呼?, 权限 }, 物品栏, bug报告 }
系统日志: [...]
```

`角色` 分两类：

```text
受控角色 {
  类型: '受控'
  优先级: 1..3            # 1 最高；默认第一个角色为 1
  档案: { 姓名, 外观, 性格, 型号, 语言习惯, 背景, 关系, 初始认知, 其他 }
  # 状态沿用现 schema 的千鹤字段（意识/电源/cpu/内存/身体/认知/电量/液位/着装/记忆/好感/系统状态…）
  # 记忆日志: 记忆条目[]（按本角色视角记录）
}
背景角色 {
  类型: '背景'
  档案: { 姓名, 外观, 关系, 备注 }
}
```

要点：

- `当前角色` 存 id，不存姓名；改名不改 id。
- 派生值 `$好感阶段` 按角色各自计算。
- 删除当前角色时回退到优先级最高的受控角色。
- `主角.测试员` 改为 `主角.持有者`；终端不再绑定 AN-0170A 型号，标题取当前角色型号。
- 不兼容旧档，`normalizeMemoryLog` 的旧对象迁移分支可删除（保留规范化逻辑）。

### 3.2 优先级与配额

| 优先级 | 记忆注入条数 | 字符预算 | 档案注入 | 面板顺序 |
| --- | --- | --- | --- | --- |
| 1 | 12 | 2000 | 完整档案 | 首位 |
| 2 | 8 | 1200 | 完整档案 | 次位 |
| 3 | 5 | 800 | 档案摘要 | 再次 |

- 钉选记忆不计入预算（沿用现有规则）。
- 配额在设置页可调，默认取上表。
- 优先级同时影响：记忆注入、档案注入详略、同场描写权重、角色列表排序。

## 六、风险

1. **变量路径重写**：`千鹤` → `角色/<id>` 波及更新规则、输出格式、脚本、界面；AI 动态键易写错，需要路径校验与容错。
2. **多角色记忆膨胀**：需要配额与裁剪，否则提示词超长。
3. **六面板全量改造**：界面工作量最大，容易漏写。
4. **千鹤预设回归**：必须有一份「与 V1.6.3 对齐」的对照清单。
5. **同步脚本硬编码**：现有 `_sync_inline.mjs` 指向稳定版，需新增分支脚本。
6. **去框架不彻底**：测试员 / 投放 / 学园分散在 13 个左右文件，容易漏改。

## 七、待拍板

1. 角色 id 规则：建议 `千鹤` 固定，其余 `c1/c2/…`，改名不改 id。
2. 向导触发时机：首楼自动弹出 / 终端按钮手动打开。
3. 背景角色上限，以及是否允许升级为受控角色。
4. 配额三档是否允许玩家在设置页修改（默认允许）。
5. `主角.持有者` 是否需要「称呼」字段（建议只留权限，称呼由玩家自述）。
