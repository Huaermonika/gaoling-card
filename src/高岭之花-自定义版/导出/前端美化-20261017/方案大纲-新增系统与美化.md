## 一、系统一：小手机 · 主屏 + APP

### 1.1 概念

把现在的「终端视图」（app-view，六面板 + 底部六标签）改成**手机主屏 + 应用图标**的形态：

- 主屏：类似手机桌面，一排排应用图标（圆角方块 + 名称），可点击进入各 APP。
- APP：进入某个应用后是全屏界面，提供返回主屏的方式（顶部返回键 / 手势 / 底部 Home 点）。
- 不追求真实手机边框（不做外壳、刘海、按键），只做"像手机"的观感：主屏壁纸感、图标质感、返回动画。

### 1.2 应用列表（初拟）

| 图标 | APP 名 | 内容 |
|------|--------|------|
| ◈ | 控制终端 | 现有六面板整体迁入（状态/认知/记忆/躯体/指令/系统），内部保留六标签或改列表导航 |
| ❖ | 状态总览 | 可单独拆出状态页作为独立 APP（可选） |
| ▤ | 记忆 | 记忆页独立 APP（可选） |
| ✥ | 躯体参数 | 躯体页独立 APP（可选，配合人体图） |
| >_ | 指令终端 | 指令页独立 APP（可选） |
| ✎ | 认知 | 认知页独立 APP（可选） |
| ⚙ | 设置 | 现有设置视图 |
| ▦ | 画廊 | 系统二（插图） |
| ✉ | 对话 | 返回对话视图 |

> 待确认：APP 拆成「六个小 APP」还是「一个控制终端 APP 内含六个面板」，见 §5 待确认项 Q1。

### 1.3 实现要点

- 新增 `home-view`（主屏）作为 `view === 'home'` 分支，现有 `app-view` 变为某个 APP 的内容。
- 主屏样式：背景沿用主题 `--bg`，图标网格（4 列），图标用内联 SVG + 主题色；主屏底部可留 dock（对话 + 设置）。
- 返回逻辑：`view` 状态机扩展为支持层级栈（home → app → …），简单实现用 `view` + `app` 两个变量即可，不引入路由库。
- 手机形态与 PC 形态都接入主屏（PC 形态主屏居中于双栏右侧区域，或独立居中，见 Q2）。

### 1.4 独立开关

设置页新增开关「小手机模式」（`homeMode`）：开 = 主屏 + APP 形态；关 = 保留现有 app-view 六标签形态。保证两个形态可切换对比，用户可决定最终采用哪个。

## 二、系统二：插图 / 画廊系统

### 2.1 概念

一个**画廊页**（APP）：网格展示插图，点开看大图、看图注/说明。先做**基础框架**（可复用的插图展示组件与数据结构），画廊页是它的第一个实例；后续任何页面都能用同一套组件挂插图。

### 2.2 基础框架（可复用部分）

- **数据结构**：`插图条目 { id, 标题, 描述, src, 标签[] }`，预览数据层静态快照一份；真实运行时从变量/本地素材读取（待定 Q3）。
- **组件**：
  - `IllustGrid.vue`：网格画廊（图 + 标题 + 标签）
  - `IllustViewer.vue`：大图查看（遮罩层、左右切换、关闭）
  - 复用现有面板头结构（panel-head / panel-icon / panel-tag / panel-desc），风格统一。
- **图片素材**：素材 URL 会过期 → 一律先下载到本地再引用（工作模式第五部分约定）。预览版用本地相对路径或内联 base64（单文件考虑体积，Q4）。

### 2.3 画廊页（第一实例）

- 作为主屏上一个 APP「画廊」。
- 内容初拟：角色立绘 / 机体设定图 / 场景图 / 彩蛋图（素材由用户提供）。
- 空状态：无图时显示「暂无插图」占位卡。

### 2.4 与现有彩蛋的关系

现有 `unlock sakura` 隐藏主题等彩蛋保留不动；画廊可作为彩蛋图的新落点（可选，不强制）。

## 三、新增元素：人体图

- 素材：用户稍后提供（已确认）。
- 落点初拟：躯体页顶部（或状态页），形式看素材后再定。
- 我的倾向建议（供参考，不作决定）：若素材是可交互人体示意图 → 放在躯体页顶部，身体锁定/损伤部位高亮联动；若素材是静态立绘/装饰图 → 状态页顶部作装饰总览。
- 约束：必须与现有面板风格融合（配色、圆角、间距一致），不突兀。

## 四、小修改项

### 4.1 记忆页 / 指令页高度不一致

- 现状：记忆页预览仅 1 条记忆、指令页指令列表为空 → 页面矮，手机端切换时与其他页高度观感不一致。
- 方案：
  1. 面板内容区统一最小高度（`min-height`，按六面板中最矮的合理观感定，如 480px 参考值，实际按主题字号调）。
  2. 空状态视觉补强：记忆为空 → 插图/引导卡；指令为空 → 引导卡（写「可在下方添加覆盖指令」）。
  3. 两页在手机端与其他页同高度观感（验证方式：切页检查无跳动）。
- 注意：PC 端双栏右栏有滚动，无此问题；只约束手机端 `pane` 高度。

### 4.2 图标重绘

- 现状：`panel-icon` 用字符符号（❖ ✎ ♡ ▤ ✥ >_ $ ⏻ ≈ ◈ ✦）。
- 方案：统一替换为内联 SVG 图标，尺寸沿用 24px（small 20px）、主题色 `var(--accent)`，风格线性、圆角、与现有图标底一致。
- 范围：六面板 + 设置 + app-tabs 标签图标 + 主屏应用图标（系统一）。
- 交付时逐枚列图标对照表。

## 五、待确认项（Q）

- **Q1**：系统一的 APP 拆法——「一个控制终端 APP 内含六面板」还是「六个独立小 APP」？（推荐：控制终端一个 APP 内含六面板，改动小且保留现有结构）
- **Q2**：PC 形态的主屏呈现——主屏居中显示于双栏右侧？还是 PC 形态不做主屏、仅手机形态用？（推荐：两形态都接入，PC 主屏居中于右栏）
- **Q3**：画廊图片来源——预览版用静态快照；真实运行从哪读？（可先用静态，运行时接入待定）
- **Q4**：预览版画廊图片引用方式——本地相对路径（.html 同目录放图）还是内联 base64（单文件但体积大）？（推荐本地相对路径，html 与图同目录）
- **Q5**：系统一的默认开关状态——默认开还是默认关？（推荐默认关，先对比再决定采用）
- **Q6**：人体图素材形式与落点（等素材到后定）。

## 六、实施顺序（建议）

1. 先做**小修改项**（4.1 高度、4.2 图标）——体量小、风险低，快速见效。
2. 再搭**系统二基础框架**（画廊组件 + 画廊页）——独立交付。
3. 再做**系统一主屏 + APP**——结构调整最大，放最后；若系统二被采用，主屏上直接放画廊图标。
4. 人体图等素材到后插入（挂靠步骤 1 或 3 之后均可）。
5. 每步完成 → 同步 .vue 底稿 + .html 预览 → 刷新预览交付 → 用户确认 → 进入下一步。
