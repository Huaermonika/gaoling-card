# 一、P0-1 角色档案字段规格

## 1.1 字段表

| # | 字段 | 控件 | 必填 | 长度 | 默认 | 注入 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 姓名 | 单行输入 | 是 | 1–20 字 | 空 | `姓名：X` |
| 2 | 型号 | 单行输入 | 否 | ≤40 字 | 空 | `型号：X`；空时终端标题显示「控制终端」 |
| 3 | 外观 | 多行输入 | 否 | ≤300 字 | 空 | `外观：X` |
| 4 | 性格 | 多行输入 | 否 | ≤300 字 | 空 | `性格：X`；空时注入「未指定（按互动自然形成，不默认高冷或机械腔）」 |
| 5 | 语言习惯 | 多行输入 | 否 | ≤200 字 | 空 | `语言习惯：X` |
| 6 | 背景 | 多行输入 | 否 | ≤500 字 | 空 | `背景：X` |
| 7 | 关系 | 多行输入 | 否 | ≤200 字 | 空 | `关系：X`（可写与持有者或其他角色的关系） |
| 8 | 初始认知 | 四个短输入 | 否 | 每项 ≤200 字 | 见 1.2 | **只写入状态，不进每轮档案块** |
| 9 | 其他 | 多行输入 | 否 | ≤300 字 | 空 | `其他：X` |

## 1.2 初始认知

拆成四项，对应 schema 的状态字段：

| 子项 | 对应状态 | 默认值（留空时） |
| --- | --- | --- |
| 身份认知 | `身份认知` | 知道自己是仿生机器人 |
| 身体认知 | `身体认知` | 清楚自己的身体是仿生机体 |
| 处境认知 | `处境认知` | 开局地点（取 `世界.当前地点`） |
| 常识认知 | `常识认知` | 现代社会的常识；仿生机器人与控制终端不对外公开 |

规则：初始认知是**开局种子**，创建时写入状态四字段；之后以状态为准，不再重复注入，避免与运行中的认知覆盖冲突。

## 1.3 校验

- 姓名：`trim` 后非空；不得为纯符号；不得与已有角色（受控 + 背景）重名；禁止换行。
- 型号：禁换行；允许字母、数字、`-`、`_`、空格。
- 多行字段：统一换行；连续 3 个以上空行折叠为 1 个；首尾空白去除。
- 档案总注入字数 ≤1500；超出时表单黄字提示，仍可保存，注入时按「姓名 → 型号 → 性格 → 外观 → 语言习惯 → 背景 → 关系 → 其他」顺序截断并写日志。

## 1.4 注入格式

每轮注入当前角色档案块（脚本生成，世界书不存）：

```text
【当前角色档案】
姓名：白峰千鹤
型号：AN-0170A
外观：黑色长发，身高约 165cm，私立清岭学园制服……
性格：自信、克制、有距离感，掌握谈话节奏
语言习惯：简短、客气、不寒暄；被冒犯时用明确语言设边界
背景：以人类学生身份就读于清岭学园 2 年 A 班……
关系：与持有者是「被控制者—持有者」，表面无交集
其他：……
```

规则：

- 空字段整行省略，不写「无」「未填写」「待填写」。
- 字段顺序固定，便于 AI 稳定读取。
- 标签用中文全角冒号，与现有世界书风格一致。
- 注入位置初定：系统深度 0（与「写作规范」同层），每轮一次；多角色时先当前角色，再按优先级列在场角色摘要。

## 1.5 多角色时的注入范围

| 角色 | 注入内容 |
| --- | --- |
| 当前角色 | 完整档案块（按 1.4） |
| 其他受控角色 | 姓名 + 型号 + 一句话摘要（性格或关系） |
| 背景角色 | 姓名 + 外观一句话 + 关系 |

摘要长度上限：其他受控角色每人 ≤80 字，背景角色每人 ≤40 字；总预算 ≤400 字。

# 二、P0-5 开局流程

## 2.1 入口

| 入口 | 行为 |
| --- | --- |
| 首楼自动 | `角色` 为空时自动打开向导；未完成前不进入正文 |
| 终端「设置 → 角色」 | 新建 / 编辑 / 导入，随时可再开 |
| 外部工具 | 生成 opening v2 JSON，卡内导入 |

## 2.2 步骤

```text
① 说明页：你是控制终端持有者
② 选择来源：千鹤预设 / 从零自定义 / 导入 JSON
③ 表单（自定义）或确认（千鹤）
④ 预览：档案卡 + 开场选择
⑤ 写入变量 + 生成首条消息
```

- **千鹤预设**：档案与状态全部内置，直接进入第 ④ 步；开场三选一（教室 / 补习 / 家访）。
- **从零自定义**：第 ③ 步填 9 个字段（姓名必填），第 ④ 步用通用开场。
- **导入 JSON**：校验格式与字段后进入第 ④ 步；可覆盖或追加角色。

## 2.3 开场生成

- 千鹤：沿用现有三条首条消息（0 / 1 / 2）。
- 自定义：**静态模板**（终端到手 → 机体接入 → 第一次连接），字段用占位符替换；不额外调用 LLM，保证稳定与零延迟。
- 后续可选增强（不进本次范围）：用 `generate` 按档案生成个性化开场。

## 2.4 写入内容

向导完成后写入：

```text
角色: { <id>: 档案 + 初始状态 }
当前角色: <id>
主角.持有者: { 权限: '完整控制权限' }
世界: { 当前时间, 当前地点, 近期事务 }
系统日志: [ 通用启动日志 ]
```

- 千鹤预设的初始状态与 V1.6.3 对齐（电量 92、冷却液 100、润滑液 60、好感 0 等）。
- 自定义角色的初始状态取默认值：电量 100、三液默认、好感 0、意识运行中、系统正常。

## 2.5 opening v2 JSON（草案）

```json
{
  "format": "gaoling/opening/v2",
  "name": "预设名",
  "holder": { "权限": "完整控制权限" },
  "characters": [
    {
      "id": "千鹤",
      "类型": "受控",
      "优先级": 1,
      "档案": {
        "姓名": "白峰千鹤",
        "型号": "AN-0170A",
        "外观": "……",
        "性格": "……",
        "语言习惯": "……",
        "背景": "……",
        "关系": "……",
        "其他": "……",
        "初始认知": {
          "身份认知": "……",
          "身体认知": "……",
          "处境认知": "……",
          "常识认知": "……"
        }
      },
      "开场": "教室"
    },
    { "id": "c1", "类型": "背景", "档案": { "姓名": "……", "外观": "……", "关系": "……", "备注": "……" } }
  ],
  "当前角色": "千鹤"
}
```

校验：至少一个受控角色；姓名唯一；优先级 1–3 且受控角色内不重复（重复时按顺序重排）；`当前角色` 必须存在；`format` 不符时拒绝导入并提示。

## 2.6 状态与回退

- 表单草稿存 `localStorage`（键 `ch:wizard-draft`），意外关闭可恢复。
- 未完成向导：首楼保持空，终端不可用，提示「请先完成初始化」。
- 重新初始化：需在设置页二次确认，清空角色表与记忆。

## 2.7 视觉

- 三形态（手机 / PC / 终端）沿用现有主题；向导本身走「控制终端」深色等宽风格。
- 步骤条 3 段；表单单列，手机端全宽；主按钮固定在底部。
- 预览卡复用终端信息卡样式，不新造组件语言。

# 三、需要拍板的点

1. 自定义开场用静态模板（建议）还是调用 `generate` 生成。
2. 初始认知四项的默认值是否采用 1.2 的写法。
3. 档案总字数上限 1500 是否合适。
4. 导入时的合并策略：覆盖 / 追加 / 询问（建议询问）。
