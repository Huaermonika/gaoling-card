## 二、P0 · 核心

### 问题 5 + 6 · 对话栏不发变量更新 + 移除 syncOps（合并处理）

**现象**：玩家用对话栏对话不再主动发送变量更新；「变量更新会检测中间值」的开关切换没有按设想工作。

**根因（已确认）**：[ui-state.ts](界面/控制终端/ui-state.ts) 的 `sendControlUpdate`：

```ts
const { updateStr } = (uiState.syncOps || forceUpdate) ? buildControlUpdate(data) : { updateStr: '' };
```

`syncOps` 默认 `false`，导致 `sendChat` 只发玩家文本、不发 stat_data diff。这是上次「确保对话栏=语言对话而非终端输入」改动的副作用。`syncOps` 开关（「检测中间值」）正是问题 6 要移除的功能。

**方案（已定）**：
1. **彻底移除 syncOps 功能及其开关按钮**；`sendControlUpdate` 改为**始终** `buildControlUpdate`（`previousState` 快照本身就能挡住中间值泄漏，无需开关）。
2. 清理 localStorage `ch:syncOps` 残留、App.vue 中对应开关 UI、ui-state.ts 中 `uiState.syncOps` 字段与 `setSyncOps`。

**涉及文件**：`界面/控制终端/ui-state.ts`、`脚本/对话显示/App.vue`。

### 问题 4 · 变量残留 / 回退 / 好感度错位

**现象**：多次游玩后卡内变量会保留之前对话的变量值且难以调整；个别情况好感度 100 仍显示冷漠疏离。

**根因（已确认）**：stat_data 全链路读写绑 `{ type: 'message', message_id: -1 }`（动态「最新消息楼层」深度索引）：
- [store.ts:23](界面/控制终端/store.ts#L23) 经 [mvu.ts](../../util/mvu.ts)
- [submodel.ts:187](脚本/对话显示/submodel.ts#L187) `STAT_ROOT`

[mvu.ts](../../util/mvu.ts) 每 2 秒轮询「最新楼层」的 stat_data，读到空值/错位就用 schema 默认值覆盖本地 data，或切 chat / 删除重开时 `-1` 解析错位读到旧值 → 残留 / 回退 / 串值。

**方案（保守，已定，不动存储位置）**：
1. **修 [mvu.ts](../../util/mvu.ts) 轮询**：读到空 stat_data 或 `schema.safeParse` 失败时，**不覆盖**本地 data（消除「玩家操作被回退」）。
2. **切换聊天 / 新建聊天时把 stat_data 重置回 initvar**（消除「残留旧对话变量值」）。
3. **错位兜底**：`-1` 读到的值与本地快照差异异常（好感度骤变等）时用 initvar 兜底。

> **⚠ 动手前必须先备份**（用户要求）：git 提交当前 message 存储模式 + 留存「改动前快照 + 修改方案 + 回滚步骤」文档，方便恢复。

**涉及文件**：`util/mvu.ts`、`界面/控制终端/store.ts`、`脚本/对话显示/submodel.ts`（如需）、`世界书/变量/initvar.yaml`。

## 三、P1 · 重要

### 问题 1 · 流式美化与预设冲突（思维链露出 + 双语注释失效）

**现象**：特定预设（含双语输出但注释掉日语）与前端美化格式冲突，出现思维链原始标记露出（掉格式），目前只适配一小部分预设。

**根因（已确认）**：
1. [streaming.ts](../../util/streaming.ts) 的 `mountStreamingMessages` 把酒馆原生 `.mes_text` 隐藏，改用 iframe 挂 Vue 自己渲染。
2. 渲染读的是 `getChatMessages(message_id).message` **原始消息文本**（[streaming.ts:71](../../util/streaming.ts#L71)），没经过酒馆预设的显示正则。
3. App.vue 的 `extractDialog` 硬编码剥离（只认固定标记），覆盖不了所有预设。

**方案（已定）**：
1. **主方案**：在 `mountStreamingMessages` 读消息处，对 AI 消息先过 `formatAsTavernRegexedString(msg, 'ai_output', 'display', {depth})`，再接给 App.vue。预设自己的显示正则（含思维链清洗、双语注释）就会生效。
2. **兜底开关**：加「是否启用美化」开关，关闭时不隐藏 `.mes_text`，回退酒馆原生显示。
3. **双语注释结论**：双语注释属 `destination='display'` 显示正则，主方案正好覆盖；我们只动 display 层、不碰 prompt 层，预设双语输出给 AI 学语境的链路不受影响。

**待验证点**：流式 token 阶段（`STREAM_TOKEN_RECEIVED`）思维链标记可能未闭合，需实测决定「流式就应用」还是「最终渲染时应用」。

**涉及文件**：`util/streaming.ts`、`脚本/对话显示/App.vue`（美化开关）。

## 六、关键研究结论备忘（实施时的技术细节）

- `formatAsTavernRegexedString(text, source, destination, {depth})` 是 `@types/function/tavern_regex.d.ts` 声明的全局函数，返回**纯文本**（非 HTML），应用酒馆预设正则。`source='ai_output'` + `destination='display'` 对应「AI 输出 + 仅显示层」正则组。
- 该函数在**脚本作用域 / 父页面**可用，但 **iframe 的 SillyTavern namespace 里没有**（`@types/iframe/exported.sillytavern.d.ts` 不含它），所以必须在 `mountStreamingMessages`（脚本层）调用，不能在 App.vue（iframe 内）调用。
- `message_id: -1` = 深度索引「最新消息楼层」，动态相对位置，不是固定楼层。
- stat_data 两个写入方：前端 `updateVariablesWith(..., {type:'message', message_id:-1})` + AI `<UpdateVariable>` 块（框架解析写 message 层）。两者都绑 message 层是系统能跑通的前提，故方案 A（改 chat 层）会断链，已放弃。
