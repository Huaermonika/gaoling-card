# 开局与角色 · 交互重设计

> 现状：开场被塞进一个「预设 / 自定义」两 tab 的表单里；官方角色和自定义角色混在同一列表；没有角色库、没有导入导出；图标是一个临时字符。
>
> 这份文档只定交互与数据边界，不改代码。确认后再替换现有 `OpeningWizard`。

## 1. 两条路，从第一屏就分开

玩家打开卡，先选的是**玩法模式**，不是填表：

```text
┌─────────────────────────────┐
│  高岭之花 · 控制终端          │
│                             │
│  ┌─────────┐  ┌─────────┐  │
│  │ 官方设定 │  │ 自定义   │  │
│  │ 白峰千鹤 │  │ 写自己的 │  │
│  └─────────┘  └─────────┘  │
│                             │
│  导入角色 / 开场              │
└─────────────────────────────┘
```

- **官方设定**：使用内置角色与官方开场，档案只读，保证体验一致。
- **自定义**：玩家写角色、选或写开场，可保存、导出、导入。
- **导入**：直接读别人分享的角色/开场文件。

两条路之后可以互通：官方角色可以「复制为自定义」再改。

## 2. 官方模式

```text
官方设定
  └ 白峰千鹤
      ├ 档案（只读）
      ├ 设定集（学校、城市、时代、身份规则，只读）
      └ 选择开场
          ├ 教室 · 初次连接
          ├ 放学后 · 单独辅导
          └ 周末 · 家中（恋人线）
```

- 官方角色有封面、徽章、档案页，排版按「设定集」做，不跟自定义混在一起。
- 开场卡片带场景、关系、时间标签，点开可读全文。
- 官方内容只读；想改就「复制为自定义」，生成一份可编辑副本。
- 以后新增官方角色，只是往这个列表里加卡。

## 3. 自定义模式

分三步，不是一张长表单：

### 第一步 · 角色

- 必填：姓名。
- 选填：型号、外观、性格、语言习惯、背景、关系、其他。
- 头像 / 立绘：从画廊选，或上传。
- 高级（折叠）：初始认知（身份 / 身体 / 处境 / 常识）。

### 第二步 · 开场

三种来源：

1. **通用开场**：根据角色字段自动生成，可直接改；
2. **自己写**：空白编辑器，附带写作提示；
3. **导入开场**：选择之前导出的开场文件。

右侧实时预览开场第一屏，确认后再进入下一步。

### 第三步 · 世界与持有者

- 持有者称呼；
- 起始地点、时间（可留空用默认）；
- 简介式的「当前处境」一句话；
- 预置记忆：默认两条（连接建立、第一次见面），可增删。

### 确认页

- 角色摘要 + 开场首段 + 世界信息；
- 「开始」/「存入角色库」。

## 4. 开场模型

开场是**角色预设的一部分**，不是酒馆 greeting：

```text
Opening {
  id, name, tags[],
  text,                  // 正文
  characterId,
  dataOverrides?,        // 世界/状态覆盖
  memories[]             // 预置记忆
}
```

- 官方开场：内置、只读。
- 通用开场：模板 + 角色字段填充，玩家可改。
- 自定义开场：玩家正文，可保存为开场预设复用。
- 开场只写一次；首楼是占位消息，选完后替换。
- 开场完成后不允许改历史；要换开场只能新聊天或「重置本聊天」。

## 5. 角色库与存储

| 数据 | 存哪 | 说明 |
| --- | --- | --- |
| 当前聊天状态 | MVU 消息变量 | 角色、世界、记忆，随聊天走 |
| 官方角色/开场 | 卡内只读 | 随卡更新 |
| 玩家角色库 | IndexedDB | 含头像/立绘、多个开场 |
| 玩家开场库 | IndexedDB | 可单独复用 |
| 最近使用 | localStorage | 记住上次选择 |

角色库是一等公民：

- 列表：封面、姓名、型号、开场数、更新时间；
- 操作：编辑、复制、删除、导出、用作新聊天；
- 一个角色可以有多个开场。

## 6. 导出与导入

导出为 `.json`（可选带图片的 `.zip`）：

```json
{
  "kind": "gaoling.character",
  "version": 1,
  "character": { "姓名": "...", "外观": "...", "...": "..." },
  "openings": [{ "name": "...", "text": "...", "memories": [] }],
  "avatar": "data:image/webp;base64,..."
}
```

- 导入时校验版本与字段，预览后选择「直接开始」或「存入角色库」；
- 重名不覆盖，生成副本；
- 开场可以单独导出/导入；
- 官方角色导出时标记 `source: official`，导入后仍是只读副本。

## 7. 入口与视觉

### 入口

- **首次进入**：占位首楼 → 启动页（官方 / 自定义 / 导入）。
- **游戏中**：设置 →「角色与开场」hub；
  - 官方：档案、设定集、当前开场；
  - 自定义：角色库、新建、导入、导出。
- 终端头部不再放临时字符图标；入口用带文字的按钮或成套图标，等美化方案统一。

### 视觉区分

| | 官方 | 自定义 |
| --- | --- | --- |
| 气质 | 设定集、徽章、书页 | 工作台、虚线框、草稿 |
| 排版 | 封面 + 章节 | 卡片 + 表单 |
| 色彩 | 沿用主题色，加官方徽章 | 沿用主题色，加「草稿」标记 |

不新增配色，只换排版、边框、徽章与文案。

## 8. 关键交互细节

- 官方模式切到自定义：提示「将复制千鹤的档案，官方原版不受影响」。
- 自定义角色名重复：允许，但列表用 id 区分。
- 导入失败：指出具体字段，不覆盖现有角色库。
- 删除角色：二次确认；正在使用的角色不可删。
- 开场写入失败：保留占位首楼，允许重试，不置完成标记。
- 旧聊天：没有占位标记就不弹启动页。

## 9. 分期

| 阶段 | 内容 |
| --- | --- |
| P1 | 启动页 + 官方模式（千鹤档案、三条开场） |
| P2 | 自定义三步 + 通用开场 + 角色库 |
| P3 | 导出/导入 + 开场库 |
| P4 | 设置 hub、图标与视觉统一 |

3. 世界设定做到哪层？建议先「持有者称呼 + 地点 + 时间 + 一句话处境」。
