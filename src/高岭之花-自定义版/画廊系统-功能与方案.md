## 3. 功能清单

### 3.1 数据层

图片记录建议字段：

```text
id, 标题, 说明, 标签[], 来源(上传/生成/卡内),
角色id?, 记忆楼层?, 时间, 宽高, 大小,
原图(blob/url), 缩略图(blob/url)
```

存储方案：

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| IndexedDB（推荐） | 可存原图，容量大，不阻塞 | 需要封装增删查、导出要转 base64 |
| localStorage | 简单，现有头像已在用 | 约 5MB 上限，几张原图就满 |
| MVU 变量 | 随档同步 | 每条消息、每次打包都带 base64，不可接受 |

建议：**IndexedDB 存图 + localStorage 存设置/索引**；头像也逐步并入画廊（可先保持现有实现，画廊只负责选图）。

### 3.2 上传

- 入口：画廊内「上传」、拖拽、剪贴板粘贴、手机相册/相机；
- 多选上传，逐张进度；
- 处理：长边压到 2048、缩略图 320、webp、修正 EXIF 方向；
- 入库时填：标题（默认文件名）、标签、关联角色、备注；
- 失败提示：格式、大小、解码失败分别提示。

### 3.3 浏览

- 手机 2 列、PC 4–5 列网格；可按「角色 / 标签 / 来源 / 时间」分组；
- 筛选与搜索：角色、标签、来源、关键词；
- 全屏查看器：缩放、拖动、左右滑、信息栏、删除/编辑/设为头像；
- 空态、加载骨架、大图渐进加载。

### 3.4 交互

- 设为头像 / 立绘（从画廊选图）；
- 关联角色、关联记忆条目或楼层；
- 批量选择：打标签、删除、导出；
- 收藏 / 封面（角色卡展示用）；
- 与角色切换联动：默认只看当前角色，可切「全部」。

### 3.5 AI 交互（范围待定）

| 能力 | 实现 | 成本 |
| --- | --- | --- |
| 让 AI 看图 | 选中图片 → `generate({ image })` 或下一轮消息附带图片 | 按图片 token 计费，`getImageTokenCost` 可预估 |
| 让 AI 出图 | 预设开启 `request_images`，模型返回图片后落库 | 取决于模型/后端是否支持 |

| 图片→剧情 | 把图片说明注入提示词，作为场景/道具 | 文本 token |

### 3.6 导出与配额

- 导出：zip（原图 + gallery.json）或 json + base64；可只导当前角色；
- 导入：合并 / 覆盖 / 仅新增；
- 配额：总容量、单图大小、数量上限；超限提示清理；
- 可选：随角色预设导出头像与封面（不导全部原图）。

## 9. 官方图 CDN 方案

### 9.1 仓库结构

```text
gallery/
  manifest.json
  official/
    千鹤/
      portrait/
        default.webp
        default.thumb.webp
        stop.webp
        stop.thumb.webp
      cg/
      meta.json          # 可选：角色级配置
```

### 9.2 地址策略

- 优先：`https://testingcf.jsdelivr.net/gh/<user>/<repo>@<tag>/gallery/...`
- 兜底：`https://cdn.jsdelivr.net/gh/<user>/<repo>@<tag>/gallery/...`
- 用 tag（如 `@gallery-v1`）或 commit 固定版本，避免 `@main` 的长缓存；换版即换 tag。
- jsdelivr 对公共仓库免费，CORS 开放，可直接 `fetch` 后写入 IndexedDB。
- 单文件约 20MB 上限；立绘建议 webp、长边 1600–2048。

### 9.3 manifest.json

```json
{
  "version": "2026-11-03.1",
  "images": [
    {
      "id": "qianhe-portrait-default",
      "character": "千鹤",
      "title": "默认立绘",
      "file": "official/千鹤/portrait/default.webp",
      "thumb": "official/千鹤/portrait/default.thumb.webp",
      "width": 1024,
      "height": 1536,
      "bytes": 320000,
      "sha256": "…",
      "tags": ["立绘", "默认"],
      "trigger": { "mode": "state", "when": { "意识状态": "运行中" }, "priority": 10, "once": true }
    }
  ]
}
```

### 9.4 更新流程

1. 新增/替换图片 → 更新 manifest 的 `version`、`sha256`、`bytes`；
2. push 并打新 tag；
3. 玩家端启动时拉 manifest（带时间戳避开缓存），对比本地 `version`；
4. 只下载缺失或哈希变化的文件，校验后入库；
5. 下载失败继续用本地缓存；首次无缓存时显示占位图。

### 9.5 维护与费用

- 费用：GitHub 公共仓库 + jsdelivr 均免费；没有服务器、域名、备案成本。
- 维护：换图 = 改文件 + 改 manifest + 打 tag；回滚 = 切回旧 tag。
- 风险：jsdelivr 偶发不可用；已缓存的图不受影响，未缓存的显示占位。
- 注意：仓库必须公开；`@main` 有缓存延迟，发布务必用 tag。

## 10. IndexedDB 结构

```text
DB: ch-gallery
  official_assets: { id, version, meta, blob, thumbBlob }   keyPath: id
  player_images:   { id, owner角色id, title, tags, blob, thumbBlob, createdAt } keyPath: id
  kv:              { key, value }                            keyPath: key
    manifest_version, last_sync, settings
```

- 原图与缩略图都存 Blob；界面只用缩略图，查看器按需读原图。
- `kv` 只放小数据；localStorage 保留角色头像映射等轻量设置。
- 导出：遍历两个 store，转 base64 写 zip/json。

## 11. 图片记录与触发配置

```text
ImageRecord {
  id, title, tags[], source: 'official' | 'player',
  characterId?, memoryFloor?, createdAt,
  width, height, bytes,
  trigger?: TriggerConfig
}

TriggerConfig {
  mode: 'state' | 'affection' | 'keyword' | 'manual',
  when?: Record<string, string>,     // 如 { 意识状态: '已停止' }
  keywords?: { word: string; weight?: number }[],
  priority?: number,
  cooldown?: number,                 // 单位：楼层
  once?: boolean                     // 每档/每聊天只触发一次
}
```

触发引擎规则：

- 只在状态**迁移**时判定，状态不变不重复；
- 关键词只看最新一条 AI 消息，按权重与具体度取最高；
- 同一图片在 `cooldown` 楼层内不重复；
- 手动固定优先级最高，退出固定后回到自动判定；
- 每次触发写一条画廊历史（时间、图片、触发原因）。

## 12. 头像迁移

- 现有 `ch:role-art:<角色id>` 存的是 dataURL / 卡图 URL；
- 改为存 `asset:<id>` 指向 IndexedDB；
- 首次启动做一次迁移：读到 dataURL → 写入 player_images → 把映射改成 `asset:<id>`；
- 读取时兼容旧值，迁移失败则保留原 dataURL 显示。


## 8. 触发规则草案（待细化）

- 只认「状态迁移」：好感阶段、意识状态在变化的那一轮触发一次，状态不变不重复。
- 关键词：按图片配置关键词表，命中最具体的一条优先；同一张图设冷却（如 20 楼）与每档只触发一次。
- 优先级：手动固定 > 意识状态 > 好感阶段 > 剧情关键词；同级按配置顺序。
- 表现：只更新「当前立绘」指针并记入画廊历史，具体显示位置等入口方案确定后再接。
- 预留：`trigger` 字段用结构化配置，后续可加地点、时间、节日等条件。
